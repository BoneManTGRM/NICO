# Phase 8: Operational Acceptance and Live Report Proof

## Objective

Convert the merged Phase 7 enforcement foundations into repeatable, retained, exact-revision operational proof for real NICO assessment runs.

## Workstreams

1. Live GitHub assessment fixture with immutable repository and commit identity.
2. Complete scanner execution ledger with command, version, exit code, applicability, stdout/stderr references, artifact hash, and assessed revision.
3. English and Spanish report-package generation from one frozen truth object.
4. JSON, CSV, Markdown, HTML, PDF, executive-summary, and appendix parity checks.
5. Rendered PDF visual inspection evidence and page-level defect capture.
6. Client-delivery gate proving incomplete or degraded evidence cannot be approved.
7. Release artifact manifest binding all operational evidence to one exact commit.
8. Post-merge regression workflow that exercises the production GitHub scope without claiming unverified provider support.

## Required retained evidence

- assessed repository identity and commit SHA
- scanner execution manifest
- CI and security results
- English report package
- Spanish report package
- machine-readable truth object
- cross-format parity result
- duplicate and unresolved-placeholder scan
- PDF rendering and visual-review record
- release decision and limitation ledger
- SHA-256 manifest for every retained artifact

## Release rules

- No synthetic fixture may be labeled as a live client assessment.
- No missing applicable scanner may be represented as complete.
- No report may be client-deliverable unless all required surfaces agree.
- GitHub remains the only production-validated provider until authenticated provider conformance evidence exists.
- No PR is merged without explicit user authorization.
