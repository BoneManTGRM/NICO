# Local backup and restore evidence import

The operations page accepts a local JSON file, previews every bounded claim and UTC/local timestamps, then fills existing fields only after the operator chooses **Confirm and fill forms — no submission**. File selection, preview, cancellation and confirmation perform no network request. Manual entry remains available. Existing authentication, operator identity, customer/project scope, API routes and server validation remain unchanged. The operator still submits backup and matching restore separately.

Exact structural schema: `backup-restore-import.schema.json`. Synthetic example: `examples/backup-restore-import.synthetic.json`. The example is NOT operational evidence: all verification flags are false and its placeholder schema will not match production. Do not submit it or substitute invented assertions. Build a real input only from reviewed provider and restore receipts; current missing facts remain false, never guessed.

Additional runtime rules, beyond JSON Schema:
- UTF-8 JSON at most16KiB, maximum supported object depth; no arrays, duplicate keys (including escaped duplicates), unknown keys or free text. No credentials, notes, URLs, account/project identifiers, actor or raw record/provider payloads are supported. All string fields are closed format/provider/method enums, SHA256 hashes or canonical timestamps. This rejects secret-bearing extra fields; no parser can establish that an arbitrary valid64hex digest was obtained honestly.
- UTC timestamps exactly `YYYY-MM-DDTHH:mm:ssZ` or `YYYY-MM-DDTHH:mm:ss.sssZ`, valid actual calendar dates, not future, restore not before backup. Preview includes current device timezone. Milliseconds and the exact UTC instant remain preserved when imported timestamps are unchanged, including ambiguous daylight-saving fall-back hours. Manual timestamp edits use existing browser-local interpretation.
- All hashes lowercase64hex. Backup reference must equal restore source reference. Both forms bind to the file's schema hash; current status must be loaded in the same customer/project scope and match at confirmation and submission. No imported schema replaces server schema.
- `pitr_applicable=false` requires a zero window. Numeric bounds mirror server limits. Flags are explicit booleans; false is permitted and remains false, which may truthfully leave readiness blocked.
- Verification scope is only `nico.restore.unreviewed-application-sample.v1`, sample_count1–3, full_bootstrap_or_http_verified=false. Preview and generated restore note disclose that full bootstrap/HTTP, approved records and whole-database equivalence were not tested. Import does not independently authenticate claims, approve a restore, or grant client-delivery authority. Notes still use the existing server hash/length behavior.

Authentication and reviewer identity are never imported. Confirmation replaces backup/restore fields, provider and generated notes; review before confirming if manual values already exist. File contents are kept only in component memory, with no browser persistence or file upload. New file selection invalidates pending reads; cancel ignores late read completions. Applying a file does not reset submission history.

Submission safety: synchronous in-flight guards prevent repeated-click writes. Current-page attempts and loaded latest evidence prevent repeat submissions of the same scoped identity. After an uncertain response, do not retry from this page; inspect/refetch durable evidence and reconcile with the operator. This is not server-side idempotency and does not guarantee deduplication across browser reloads, devices or older non-latest audit records. No new endpoint or storage is introduced. Existing backup fields remain in place after successful recording so the matching restore can be submitted without retyping. Existing populated restore references are never silently overwritten by backup submission.

Validation: isolated React hook/event harness with mocked fetch tests file cancel/reimport, async cancellation, explicit confirmation, two-step requests, credentials retained in memory, exact dates, scope/schema drift and uncertain-write protection. These are local browser-logic contracts, not real iPhone/Safari or production evidence. Live private page/API access and evidence registration were not performed. Native file picker/mobile accessibility remains a supported-browser qualification step before product signoff.
